
### [Part 2. 멘토용] 정답 및 1줄 해설 치트시트

#### A. 코드 문제 정답

1. **`'홍'` (1글자만 저장)** — `C`는 길이를 지정해야 하는 **Incomplete Type**이라, 길이를 생략하면 기본값 **1자리**로 잡혀 뒤 글자가 소리 없이 잘린다.


2. **`TYPE`** — `TYPE`과 `LIKE`의 기준은 '외부 vs 내부'가 아니라 '설계도(메모리 X) vs 실제 변수(메모리 O)'다. `TYPES`는 내부에 있어도 메모리가 없는 설계도이므로 `TYPE`을 쓴다.


3. **`(B)` 에러** — `gt_scarr`는 여러 행이 들어있는 표(Internal Table)라서 "몇 번째 줄의 `carrid`인지" 알 수 없다. 1행짜리 작업대인 `Work Area(gs_scarr)`에만 필드 값을 직접 넣을 수 있다.
4. **메모리에 그대로 남아 있다.** — `CLEAR`는 메모리 해제(GC)가 아니라 방은 유지한 채 **안에 든 모든 필드의 값만 초기값(공백/0)으로 비우는** 명령어다.



#### B. DDIC 상황 판단 정답

5. **Domain은 공유, Data Element는 분리** — 기술적 서식(8자리 날짜)은 **Domain** 하나로 통일하고, 업무적 의미와 화면 라벨('입사일'/'퇴사일')은 **Data Element**로 따로 정의한다.


6. **통화 참조 필드(Reference Table / Reference Field) 누락** — 금액(`CURR`)이나 수량(`QUAN`)은 화폐 단위(`CUKY`)·수량 단위(`UNIT`) 없이는 소수점과 의미를 해석할 수 없어 참조 연결이 필수다.
7. **다국어 지원(언어별 설명 관리)** — 같은 계정 코드라도 한국어·영어·일본어 설명을 각각 저장해야 하므로, 마스터 정보(`SKA1`)의 중복을 막기 위해 언어 키(`SPRAS`)가 포함된 텍스트 테이블(`SKAT`)로 분리한다.
8. **View Cluster + SE93** — 계층형 유지보수 화면 묶음은 **View Cluster**, 사용자 전용 T-code 바로가기 생성은 **SE93**을 사용한다.

#### C. OX 퀴즈 정답

9. **X** — UI5는 브라우저(Presentation) 영역이며, Gateway / OData(브릿지)를 거쳐 백엔드(ABAP)를 통해 데이터를 주고받는다. *(지도 1 참고)*
10. **X** — Structure는 여러 테이블에 끼워 넣거나(`Include`) 프로그램에서 참조하기 위한 빈 서식(템플릿)일 뿐 DB에 데이터를 저장하지 않는다.


11. **O** — `MANDT`를 최상단 키로 둠으로써 하나의 물리적 DB 테이블 안에서 클라이언트(예: 100번 개발, 200번 테스트 등)별 데이터를 안전하게 분리한다.
12. **O** — Check Table 기반 Foreign Key는 SQLD의 **참조 무결성** 역할을 하며, 프로그램 코드(`IF`)로 일일이 막지 않아도 DDIC 레벨에서 잘못된 코드 입력을 차단해 준다.
